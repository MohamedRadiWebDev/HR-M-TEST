# نظام الحضور والانصراف (HR Attendance)

تطبيق ويب (**Next.js 16 + React 19 + TypeScript**، تصدير ثابت `output: "export"`) لمعالجة بصمات الحضور وحساب التأخير والانصراف المبكر والغياب والجزاءات والإجازات والمؤثرات، وتصدير تقرير Excel جاهز للرواتب.
**يعمل بالكامل داخل المتصفح (بدون سيرفر)**: البيانات تُحفظ محليًا في IndexedDB.

## التشغيل

```bash
npm ci
npm run dev        # http://localhost:5000
npm run verify     # فحص الأنواع + الاختبارات + البناء (المخرجات في out/)
```

| أمر | الوظيفة |
|---|---|
| `npm run check` | فحص TypeScript (التطبيق **والاختبارات**) |
| `npm test` | اختبارات Vitest |
| `npm run build` | بناء الإنتاج إلى `out/` (موقع ثابت: Vercel / Replit Static / أي استضافة). نستخدم webpack عمدًا (`--webpack`) لثبات النتائج بين التطوير والإنتاج |

## سير العمل

1. **استيراد الموظفين** (`.xlsx`): الكود، الاسم، تاريخ التعيين/ترك العمل، **بداية الوردية**… إعادة استيراد موظف موجود **يحدّثه** (الخلايا الفارغة لا تمسح بيانات موجودة).
2. **استيراد البصمة** (`.xlsx`): عمودان (الكود، الوقت). الصيغ المدعومة: `dd/MM/yyyy h:mm AM/PM` (وص/م)، `yyyy-MM-dd HH:mm`، وأرقام Excel.
3. **المؤثرات / التسويات / الإجازات / القواعد**: من صفحاتها (قوالب جاهزة للتحميل).
4. **معالجة الحضور** ثم **تصدير التقرير** (ورقتان: تفصيلي وملخص + سجل).
5. **نسخ احتياطي**: صفحة «النسخ الاحتياطي» (ضغط حقيقي + تشفير اختياري بكلمة مرور).

## قواعد العمل (مكان واحد: `client/src/engine/config.ts`)

| القاعدة | القيمة الافتراضية |
|---|---|
| الوردية | تبدأ من `shiftStart` الخاص بالموظف (افتراضي 09:00) وتدوم 8 ساعات |
| يوم السبت | يبدأ بعد ساعة من بداية الوردية ويدوم 6 ساعات (09:00 → 10:00–16:00) |
| سماحية التأخير | 15 دقيقة (بدون خصم) |
| جزاء التأخير | أكثر من 15 د = ربع يوم • أكثر من 30 د = نصف يوم • أكثر من 60 د = يوم كامل |
| انصراف مبكر / سهو بصمة | 0.5 لكل منهما |
| الغياب | يُسجَّل 1 ويُحتسب في الإجماليات **×2** (`absenceWeight`) |
| غياب بعذر | **بدون جزاء** (`excusedAbsencePenalty = 0`، غيّرها إلى 1 لاعتباره خصمًا) |
| الإضافي | يبدأ بعد ساعة من نهاية الوردية، بالساعات الكاملة |
| بصمة واحدة بعد منتصف الوردية | تُعتبر **خروجًا** مع «سهو بصمة دخول» (وليست تأخيرًا) |

حساب إجمالي الجزاءات موجود في دالة واحدة (`summarizePenalties`) تستخدمها ورقة التفصيل وورقة الملخص ولوحة التحكم، فلا تختلف الأرقام بينها.

## الوقت والتوقيت الصيفي (مهم)

البصمة تُخزَّن كـ **wall-clock** (التوقيت المعروض على جهاز البصمة) داخل `Date` حقولها الـ UTC هي الساعة الحقيقية. لذلك النتائج **لا تتأثر بتوقيت المتصفح ولا بالتوقيت الصيفي المصري**. لا تستخدم `getHours()` على بصمة؛ استخدم `shared/wallclock.ts`.

## المعمارية

```
shared/            schema (Zod) + تطبيع التواريخ/الأوقات/البصمات + wall-clock + فترة الرواتب
src/
  app/             مسارات Next.js (كل page.tsx يعيد تصدير شاشة من views/) + layout + providers
  views/           الشاشات (Dashboard, Attendance, Employees, Settings …)
  engine/          محرك الحضور (config, shifts, scope, effects, penalties, overtime, notes, worker)
  data/storage.ts  **نقطة الفصل** بين التطبيق ومكان التخزين (حاليًا IndexedDB)
  store/           Zustand + طبقة IndexedDB
  effects/         استيراد المؤثرات + مزامنتها مع الحضور والإجازات
  exporters/       تقرير Excel (ExcelJS) وقوالب الاستيراد
  backup/          النسخ الاحتياطي (fflate + AES-GCM) والاستعادة والتحقق
  features/attendance/   مكونات صفحة الحضور
```

* المعالجة تعمل داخل **Web Worker** (لا تجمّد الواجهة) مع رجوع تلقائي للـ main thread.
* المؤثرات اليومية يقرأها المحرك **مباشرةً** من مخزن المؤثرات؛ مؤثرات «إجازة رسمية/تحصيل» تتحول لإجازات موسومة `source = "effects"` وتُعاد بناؤها مع كل تغيير.

## الخصوصية

* التطبيق يخزن بيانات شخصية (الرقم القومي، العناوين، الهواتف). تُخفى في الواجهة حتى الضغط على «إظهار».
* النسخ الاحتياطي يمكن تشفيره بكلمة مرور (AES-256-GCM). **لا ترفع ملفات الموظفين أو البصمة إلى Git** (`.gitignore` يمنع `*.xlsx` و`attached_assets/`).
* لا توجد أي طلبات شبكة خارجية (الخطوط مُضمَّنة محليًا).
* البيانات داخل متصفح المستخدم غير مشفرة (IndexedDB). استخدم حساب/جهاز موثوق.

## الأمان والاعتماديات

* لا توجد ثغرات `critical`. المتبقي في `npm audit` (9، متوسطة/عالية) كلها في سلسلة **Tailwind CSS v3 وقت البناء فقط** (`braces/micromatch/fast-glob`…) ولا تصل للمتصفح ولا تعالج ملفات المستخدم. لا يوجد إصلاح متاح داخل الإصدار 3؛ الحل الكامل هو الترحيل إلى Tailwind v4 (مسار منفصل لأنه يغيّر مظهر الواجهة).
* تمت إزالة `xlsx` (SheetJS) لعدم وجود إصلاح منشور على npm، واستُبدل بـ `exceljs` لكل القراءة والكتابة (صيغة `.xlsx` فقط).

## الاختبارات

اختبارات الوحدة والتكامل لكل ما سبق: المحرك، التطبيع، الـ store، IndexedDB (`fake-indexeddb`)، النسخ الاحتياطي والتشفير، المؤثرات، الأداء. شغّلها بـ `npm test`.

## الترحيل من الإصدار 1

عند أول فتح، يُحوَّل تلقائيًا ما كان محفوظًا في `localStorage` (بما فيه المؤثرات) إلى IndexedDB، وتُحوَّل أوقات الدخول/الخروج القديمة إلى توقيت القاهرة الصحيح. النسخ الاحتياطية القديمة (v1) تُقرأ كما هي. **البصمات لم تكن تُحفظ في الإصدار 1** فاستوردها مرة واحدة وستبقى محفوظة بعد ذلك.

## نهج «محلي أولًا»

* **لا يوجد باك اند ولا قاعدة بيانات حاليًا**: كل البيانات في IndexedDB داخل متصفح المستخدم، والتطبيق موقع ثابت.
* **كل التخزين يمر عبر `src/data/storage.ts`**. عند الانتقال لقاعدة بيانات نكتب `StorageAdapter` جديد هناك (ثم نشغّل Next في وضع الخادم بحذف `output: "export"` لتفعيل route handlers وmiddleware) دون لمس الشاشات أو المحرك. الـ adapter الحالي يحفظ لقطة كاملة؛ الميزات الجديدة الكبيرة (الطلبات، الرواتب…) نبنيها بـ **repositories لكل كيان** من البداية.
* ⚠️ **حدّ مهم للوضع المحلي**: لا توجد حسابات ولا صلاحيات حقيقية؛ أي شخص يفتح المتصفح يرى كل شيء، وكل جهاز له بياناته الخاصة. لذلك بوابة الموظف في هذه المرحلة **نموذج وظيفي** (عرض كموظف / عرض كـ HR) لبناء الشاشات والـ workflows وتجربتها، وليست مكانًا لبيانات حساسة حقيقية. الأمان الحقيقي (دخول + صلاحيات على الخادم) يأتي مع قاعدة البيانات.

## فترة الرواتب

شهر الرواتب إعداد (`الإعدادات`): الافتراضي **24** = من 24 الشهر السابق إلى 23 (أكتوبر 2026 = 24/9 → 23/10). `1` = الشهر الميلادي. يظهر كاختيار «رواتب أكتوبر 2026» مع أسهم السابق/التالي في الحضور ولوحة التحكم.

### خريطة الطريق (محلية)
1. **(تم)** Next.js + إعدادات فترة الرواتب + سياسة التأخير + طبقة التخزين المعزولة.
2. بوابة الموظف: لوحتي، ملفي، حضوري، التقويم، الإشعارات (مع «عرض كموظف»).
3. الطلبات ومسار الموافقات (إذن، إجازة، مأمورية، تصحيح بصمة، **إضافي مكتشف من البصمة**) تتحول عند الموافقة إلى مؤثرات تلقائيًا + أرصدة الإجازات.
4. قسائم الراتب، السلف، المكافآت، الخصومات (مع الاعتراض).
5. المستندات، العهد، الإعلانات، الاستبيانات.
6. الانتقال لقاعدة بيانات + حسابات وصلاحيات.
